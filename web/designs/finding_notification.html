Ownership check missing on 3 thread routes

These routes let a signed-in user start a run on a thread that belongs to someone else. We've drafted a fix that uses the same check as your other thread routes.

What's happening

Each route reads thread_id from the URL, loads that thread, and starts a run on it. The caller must be signed in, but the route doesn't check that the thread belongs to them.

So a run can read and add to another user's thread history if the caller knows or guesses its ID.

What's missing

Your other /threads/{thread_id} routes filter by owner. These three load the thread by ID alone.

✓ GET /threads/{thread_id}
select(ThreadORM).where( ThreadORM.thread_id == thread_id, ThreadORM.user_id == user.identity )
! POST /threads/{thread_id}/runs
session.get(ThreadORM, thread_id) no owner filter

12 of 15 thread routes check ownership. These 3 don't.

Proposed fix

api/runs.py +14 −9 
@@ helper, shared by all three routes @@async def get_thread_for_user(session, thread_id, user):    thread = await session.scalar(        select(ThreadORM).where(            ThreadORM.thread_id == thread_id,            ThreadORM.user_id == user.identity,        )    )    if not thread:        raise HTTPException(404, "Thread not found")    return thread @@ @router.post("/threads/{thread_id}/runs") @@async def create_run(thread_id, body, user):    thread = await session.get(ThreadORM, thread_id)    if not thread:        raise HTTPException(404, "Thread not found")    thread = await get_thread_for_user(session, thread_id, user)    return await start_run(session, thread, body, user)
Same one-line change in /runs/stream and /runs/wait.
  • Same owner filter your other 12 thread routes use.
  • Returns 404 rather than 403, so thread IDs can't be probed.
  • Includes a test: another user's request to each route gets 404.

Proof of concept
